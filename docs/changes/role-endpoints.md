# MCP Endpoint 按角色归属

2026-10-08。替代旧 Endpoint 规格中的领域分类和多角色共享连接方案；统一 ReAct、手动工具绑定、五个业务工具、安全与写操作确认边界不变。

## 需求与验收

- 连接目录按已有角色筛选、搜索，配置表单选择“所属角色”，不填写 CRM/MES 分类。
- 一个角色可拥有多个连接；只能绑定自己的连接。空连接/空工具集合仍有效，新增工具不自动授权。
- CRM、MES、知识库、工作流继续作为连接内部的工具模块、领域筛选和模糊搜索依据；不同角色复用 Tool 实现，不共享执行授权。
- 绑定保存、Agent 准备工具、每次执行和 MCP 入口均校验角色归属；目录角色与部署角色不一致时检查失败。
- 角色修改使执行修订号失效。若已有其他角色绑定连接，不能直接转交；应先解除旧关系。
- 升级不得重置已有工具选择，不删除历史连接与审计。旧默认连接安全迁移；其余无法确认归属/部署的连接停用，待人工处理。

## 设计

```text
Role / Agent 类别
  └─ 本角色的 Endpoint（role_id；可以多个）
       └─ 按领域组织的工具目录
            └─ 手动勾选 ToolRef → 统一 ReAct
```

MySQL `mcp_endpoints.role_id` 是连接归属；旧 `category` 列仅保留历史数据，不对外作为分类。管理写入要求角色已存在，Go 内部绑定/授权接口重复检查归属。角色–Endpoint–Tool 关系及版本机制保持不变。

MCP 部署定义为 `id/role_id/path/domains`；目录元数据包含 `opspilot/endpointId`、`opspilot/roleId`。Python 校验两项与登记数据一致；MCP 在接受签名后独立检查 `context.role` 等于部署角色，再查 Go 的当前授权。`domains` 限制可注册的内部模块，不是连接分类，也不授予角色调用权。

默认部署只有运营顾问连接：`business / consultant / http://127.0.0.1:3100/mcp/consultant`，目录保留五个契约；稳定 ID `business` 避免改写旧 ToolRef。尚未接通的 SOP/工作流不暴露给模型执行。其他角色可由维护者后续预置，并同时配置部署定义、网络白名单和凭据范围；本轮不添加角色创建系统。

错误：跨角色绑定/执行 `FORBIDDEN_ENDPOINT`，目录归属不一致 `ENDPOINT_ROLE_MISMATCH`；MCP 拒绝跨角色签名 `FORBIDDEN_TOOL`。旧 API 的 `category` 字段因严格 Schema 被拒绝。停用/修订号/版本冲突沿用已有安全错误处理。

一次性迁移 `mcp-role-endpoints-v3`：不改变角色工具集合或角色版本；更新连接版本/执行修订号并写配置审计。仅项目已知旧默认地址自动改为顾问路径，保留人工名称和启停选择；旧未归属或冲突连接停用，不删除。重复启动不重置配置。自定义白名单若不含新地址，不自动放行。
