# 可见执行 Trace：需求草案

日期：2026-10-09。阶段：用户已确认并授权直接开发；设计与实施记录见同目录 trace-design.md、trace-tasks.md。

## 1. 目标与当前差距

作为项目开发者，我希望在页面上按实际发生顺序查看一次用户请求中的消息、工具调用、工具结果和错误，从而还原 ReAct 执行过程，并为后续角色 Agent 评测提供可核对的记录。

当前聊天响应只有成功的工具记录与最终展示回答；ReAct 中间模型消息没有完整保留，工具失败可能只留下请求错误。现有前端的工具折叠区不是完整 Trace，不能靠把这些成功记录重新排序来实现。

本需求中的“一轮”指一次用户请求及其引发的完整 ReAct 运行，可以包含多次模型调用。它不等于一次模型调用，也不代表已实现历史会话记忆。

## 2. MVP 范围

- 新增独立的“执行 Trace”页面；聊天中每个请求提供“查看本轮 Trace”入口。
- 页面有运行列表与单次运行详情；可按请求 ID 定位运行。
- 展示本轮用户消息、可见模型消息、工具调用与对应结果，以及结束状态。
- 支持执行中查看已发生的事件、结束后回看、页面刷新后重新查询已完成运行。
- 先覆盖当前聊天 ReAct，包括 `activate_skill` 本地控制调用；保持现有聊天、权限、Skill、MCP 和审批行为不变。
- 回访创建任务的聊天 Trace 展示真实创建事件和 Task ID；后台提案、人工决策和批准后的提交属于独立执行阶段，不伪装为聊天请求中的模型步骤。后台 Task Trace 的完整接入另行迭代，现有 Task 审计仍是查询这些阶段的入口。

## 3. 用户故事与验收标准

### TR-01：运行列表与详情

作为开发者，我希望区分每一次请求，而不是把不同轮次的事件混在一起。

1. WHEN 发出一条聊天请求 THEN 系统 SHALL 为该运行提供可关联请求 ID 的 Trace 标识。
2. WHEN 打开 Trace 列表 THEN 页面 SHALL 展示问题摘要、角色、开始时间、状态，并能进入详情。
3. WHEN 从聊天的“查看本轮 Trace”进入 THEN 页面 SHALL 定位到该请求，而不是默认显示最新请求。
4. WHEN 页面刷新或 Agent API 重启后查询已完成 Trace THEN 系统 SHALL 返回先前保存的运行记录。
5. WHEN 指定不存在或无权读取的 Trace THEN 系统 SHALL 安全拒绝，不返回其他身份的事件。

### TR-02：真实消息与调用顺序

作为开发者，我希望看到模型与工具之间实际交换的内容。

1. WHEN 用户消息进入运行 THEN Trace SHALL 记录真实输入。
2. WHEN 模型响应 THEN Trace SHALL 记录实际可见内容及本次响应提出的工具调用；即使内容为空但存在工具调用，也不得隐藏该模型步骤。
3. WHEN 展示工具调用 THEN 页面 SHALL 显示工具名称、模型函数别名、本次调用 ID、参数和可获得的 Endpoint 来源。
4. WHEN 工具返回 THEN Trace SHALL 通过调用 ID 关联对应结果，展示执行状态、可获得的耗时和脱敏后的实际结果。
5. WHEN 存在多个模型—工具循环 THEN 页面 SHALL 按真实事件序号展示，不能把所有调用集中在最后。
6. WHEN 初始系统消息或运行中有效的系统说明变化可被记录 THEN 页面 SHALL 提供折叠的脱敏查看方式，区分初始说明和后续变化，不把内部凭证视作消息内容。
7. WHEN 模型原始最终消息经过引用校验或服务端处理 THEN Trace SHALL 区分“模型输出”和“最终展示回答”，不得把处理后的文案冒充原始模型消息。

### TR-03：并行与控制调用

作为开发者，我希望时间线反映真正的执行关系。

1. WHEN 一次模型响应提出多个工具调用 THEN Trace SHALL 将其归属到同一模型步骤，并分别关联结果。
2. WHEN 并行调用以不同顺序完成 THEN 页面 SHALL 保留实际完成顺序，并能按调用 ID 辨认归属，不编造串行依赖。
3. WHEN 调用 `activate_skill` THEN 页面 SHALL 标明其为“本地 Skill 控制”，不标为 MCP 业务工具。
4. WHEN Skill 收紧工具范围 THEN Trace SHALL 可查看此次启用的 Skill 与脱敏后的工具范围，不泄露执行签名或审批证明。

### TR-04：失败也是 Trace

作为开发者，我希望知道请求在哪一步失败。

1. WHEN 模型失败、工具超时、参数错误、越权或引用校验失败 THEN Trace SHALL 保留已发生事件，并记录安全错误码及失败阶段。
2. WHEN 模型提出工具调用但策略拒绝执行 THEN 页面 SHALL 标为“调用被拒绝／未执行”，不得捏造成功工具结果。
3. WHEN 没有调用任何工具 THEN Trace SHALL 正常展示消息与结束事件，不要求补出工具步骤。
4. WHEN 运行异常结束 THEN 页面 SHALL 与成功运行明确区分；已成功执行的业务副作用不能因 Trace 失败被显示为未发生。
5. WHEN Trace 采集或保存不完整 THEN 系统 SHALL 明确标注不完整或不可用，不重新执行业务工具来补日志，不将缺失事件解释为未调用。

### TR-05：可读与安全

作为开发者，我希望能快速理解事件，并且不会因查看 Trace 泄露凭证。

1. WHEN 查看详情 THEN 页面 SHALL 展示时间、事件类型、状态和摘要，支持展开消息、参数及 JSON 结果。
2. WHEN 输出内容较大 THEN 页面 SHALL 有展开或分页方式；若记录被截断，必须标明，不能使后续评测误认为内容完整。
3. WHEN 请求处于执行中 THEN 页面 SHALL 可更新已发生事件；首版不要求逐 Token 输出。
4. WHEN 序列化任意事件 THEN 系统 SHALL 在服务端移除或脱敏 API Key、Authorization、内部服务令牌、MCP 密钥、签名、Task grant 与租约令牌；不依赖前端隐藏。
5. WHEN 记录错误 THEN 系统 SHALL 使用安全错误码，不原样公开可能包含请求头或凭证的第三方异常。
6. WHEN 获取 Trace THEN 系统 SHALL 校验所属身份和角色；本机 development 演示身份不是生产登录认证。
7. WHEN 查看消息 THEN 页面 SHALL 只展示实际可观测消息，不编造思考过程，不承诺获取模型隐藏思维链。

## 4. 非目标

- 本轮不实现 30 条评测集、LLM 裁判、评分报表或自动 Prompt 优化。
- 不接入第三方托管 Trace 平台，不将记录自动上传到外部服务。
- 不新增业务 Tool、不改变统一 ReAct、不增加意图 Router。
- 不允许通过 Trace 页面重放写操作、修改审批结果或执行任意工具。
- 不实现完整多轮会话记忆、逐 Token 流式消息或全部后台 Task 执行阶段的 Trace。
- 不以 Trace 替代真实业务状态、Task 审计或权限校验；不宣称完整生产可观测性。

## 5. 最低验证场景

1. “你好”：用户消息、模型响应、结束；零工具调用。
2. 查询 C1001：用户消息、模型工具请求、客户工具调用与结果、模型最终消息、展示回答。
3. 查询概览和工单：支持多调用关联以及实际并行完成顺序。
4. 客户洞察：本地 Skill 控制、受限工具集合、CRM/SOP 结果、原始引用消息与最终编号回答。
5. 非法参数／未绑定工具：记录模型请求及拒绝原因，业务未执行。
6. 模型／MCP 失败：先前事件保留，运行标记失败，可定位阶段。
7. 回访创建：聊天 Trace 关联真实 Task ID，不虚构后台执行；仍要求人工确认。
8. 脱敏、跨身份访问、内容截断、历史查询与刷新：均有明确断言。
